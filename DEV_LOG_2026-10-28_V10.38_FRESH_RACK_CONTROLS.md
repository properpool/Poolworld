# Pool World v10.38 — fresh-rack shot-control reset (28 October 2026)

## Reproduced user-visible defect
Starting NEW RACK, or reracking after an 8-ball break, retained the previous game's power, side spin and top/backspin. A 5% finesse setting could silently become the next break shot's 5% setting, giving an unexpectedly weak break; an old English setting could also alter the new break. The unchanged baseline's 5% break impulse was 1.1138072432546986 simulation units versus the default 45% break impulse of 4.960222070374153 units. These are browser simulation units, not measured physical cue speed.

## Mandatory regression
Added `tests/test_pool60_rack_control_reset.py` (124 checks) and registered it in `.github/workflows/poolworld-staging-tests.yml`. Four viewports: 360x800, 390x844, 844x390 and 768x1024. For previous power settings 5%, 75% and 100% with nonzero side/follow, exercise both the NEW RACK button and an automatic rerack after an 8-ball break. Verify 45% selected power, zero English, UI slider synchronization, fresh match state, the actual calibrated break impulse, no inherited spin and no JavaScript errors.

## Exact passing implementation
Added `freshRack()`, called by the NEW RACK button and the automatic 8-ball break rerack. It calls the existing neutral `rack()` state reset, then selects 45% power and clears side spin and top/backspin in both authoritative state and visible controls. The internal `rack()` primitive remains unchanged for deterministic simulation and existing fine-aim tests. This resets *only a new game's controls*, not the shot-speed calibration or in-progress shots.

All four approved v3.9 audio data URIs remain unchanged.

## Release restrictions
This is a Chromium regression-tested new-game control fix. It is NOT a demonstrated improvement to ordinary moving-ball smoothness, general shot feel, GPU FPS, touch latency or visuals on the physical Samsung Galaxy A37. Independent physical-device testing and human acceptance remain RELEASE-BLOCKING. Never promote to production without both and explicit user approval.
