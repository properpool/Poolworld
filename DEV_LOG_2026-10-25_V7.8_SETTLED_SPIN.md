# Pool World v7.8 — stationary spin reset (25 October 2026)

## Reproduced defect
The shot-completion routine zeroed translational velocities but left each ball's `spin` and `follow` untouched. The engine only advances rotational decay while a shot is active, so object balls could remain frozen with rotational energy across turns. A later collision could inherit tangential throw from that stale state.

The new mandatory `tests/test_pool60_settled_spin.py` covers four viewports (390×844, 844×390, 768×1024, 1366×768), legal continuation, scratch and cue recovery, winning 8-ball, and a naturally simulated spun shot. It checks zero linear and rotational motion on all 16 balls, state transitions, no browser exceptions, and shot termination. Tests explicitly remain Chromium-only.

Baseline workflow run #177 (ID 40235646625) FAILED the new test with **644/1044 passing** and **400 residual-spin/follow failures**. Earlier #176 (ID 40235638866) passed the prior suites before the workflow required this test.

## Correction
Gameplay candidate `POOL_WORLD_6.0_STAGING_MATCH.html` commit `996dc04df539e5115014ba95ca0f5a7657355f80` now resets `vx`, `vy`, `spin`, and `follow` for all balls when `resolveShot()` declares the table settled, while retaining the resting roll quaternion `rollQ` for visual continuity. No changes to shot calibration, audio data, game monetisation, online features, or production.

New test commit `edba5683ca9c64eaf99ff8ca8a3a1a56152693fc`; workflow commit `e61d656024a5c149cabcde40477dde761480243f`.
