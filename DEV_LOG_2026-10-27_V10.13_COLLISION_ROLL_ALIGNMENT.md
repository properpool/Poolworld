# Pool World v10.13 — post-collision ball-roll alignment
27 October 2026 UTC · development branch only

## User-visible defect and reproducible baseline

The 120Hz physics integrator updated each ball's visible rolling quaternion
immediately after free-flight, cushion and jaw constraints, **before** resolving
ball-ball impulses, positional overlap correction, the second jaw pass and
rail-side contact projection. After a collision the final ball centre could
move substantially without its visible stripe/measle texture rotating with
that final displacement. This is texture skidding, not evidence of a Samsung
frame-rate defect.

New mandatory Chromium regression:
`tests/test_pool60_collision_roll_alignment.py`
(commit `a92231f9207e8ccbd3eec862caf171089c0f7add`).
Workflow registration: `f8e185aa364277a2f1ab878a8aa0f585d420b625`.
The suite covers head-on, glancing, diagonal and rail-side impacts at
390×844, 844×390, 768×1024 and 1366×768. It verifies real collision
momentum transfer, first contact, safe separation, finite physics, and each
ball's orientation against its **final** per-tick centre displacement.

The unchanged implementation failed **32 of 116** new checks in deliberate
baseline workflow #378, ID `40462188254` (84/116 passing).
For example, the 390×844 head-on impact had approximately **0.184 rad**
(10.5°) of sphere-orientation mismatch on both cue and object balls. The
test-only workflow #377, ID `40462177378`, passed all previously mandatory
suites. Both jobs and decoded logs were inspected.

## Release limitation and next priorities

This fixes a **reproduced Chromium-level collision texture/position mismatch**.
It does not establish improved physical Samsung Galaxy A37 frame rate,
smoothness, shot strength, aiming comfort, visual quality or human acceptance.
Independent physical-device/human acceptance and explicit user approval remain
release blockers; never update production without both.

The user's unchanged negative phone feedback is still the primary signal.
Next work should address the mobile presentation and actual normal-frame-rate
game feel, not count technical micro-optimisations as device acceptance.
