# Pool World v10.41 — sideways power-slider slip safety
28 October 2026 · development/poolworld-match-engine only

## User-visible defect and reproducible baseline
A player who had selected 75% power could touch the bare power track at
another height, move the finger sideways (perpendicular to the power
control), and release without pulling along the slider. The old pointerup
handler treated that sideways swipe as a stationary bare-track tap and
silently replaced the chosen power with the absolute position under the
finger. On a 360x800 Chromium viewport, a 75% selection became 24%,
reducing the non-break shotSpeed impulse from 6.5129425578 to 2.5753058306.
A 40%-track sideways swipe instead changed 75% to 43%.
The same class of defect was reproduced in portrait BIG TABLE focus mode.

The new mandatory test
`tests/test_pool60_power_cross_axis_slip.py` exercises 100 checks across
360x800, 390x844, 844x390 and 768x1024 viewports, including rotated
portrait focus mode. It checks cross-axis slips in both directions, the
actual shotSpeed impulse, no accidental firing/stuck pointer capture,
intentional stationary bare-track taps and genuine handle pulls.

## Implementation
Store the power pointer's initial cross-axis CSS coordinate and whether it
ever travelled more than 12 CSS pixels perpendicular to the slider. A
bare-track touch is an intentional absolute power tap only if it remained
within that cross-axis threshold. Track the maximum sideways excursion
during pointermove as well as the final release coordinate, so a sideways
swipe that returns to its starting point cannot masquerade as a tap.
The same rule applies to the rotated portrait BIG TABLE power control.

Normal along-track power drags, quick coalesced release calculations,
deliberate stationary bare-track taps, the wider thumb target, pointer
capture and gesture cancellation are preserved. No shotSpeed tuning,
physics, six-pocket geometry, match rules, table rendering or audio
recordings were changed.
