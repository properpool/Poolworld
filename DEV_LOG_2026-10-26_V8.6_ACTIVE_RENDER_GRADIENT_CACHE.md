# Pool World v8.6 — active-shot Canvas2D allocation audit (26 October 2026)

## Scope and baseline
Development branch `development/poolworld-match-engine` only. User reports unsmooth shots on a physical Samsung Galaxy A37; this report does **not** establish physical-device performance or human acceptance.

The prior v8.5 moving full rack created **768 radial and 336 linear CanvasGradients over 48 active frames** (16 shell gradients and seven stripe-band gradients each frame). New mandatory browser test `tests/test_pool60_active_render.py` (commit `c01e0a24c1c7f99660a09e6da14ccc61ec64ecf9`, workflow `21fbe72f3a305f850c923db19c4fb7beb77200c7`) reproduces actual active rendering and measures p50/p95/p99 render-call CPU durations across four viewports. Baseline push workflow #218 (`40275080235`) failed exactly **8 of 32** new checks: both per-frame gradient allocation assertions on all four viewports. Other 24 new checks passed. Baseline job and decoded logs inspected.

## Fix
Gameplay candidate commit `98807f50653f9bb32ac5bbf94a3b2675895fecbc`, blob `88c0986a3ceda6ea0140fb5befef7078025d7204`:
- Cache 16 coloured ball-shell sprites and seven stripe-band textures on small 2x-resolution offscreen canvases at initialization.
- Draw the cached shell and stripe textures during movement, keeping dynamic roll quaternion/stripe angle and width, cue-ball measle markers, numbered badges, shadow, stroke and specular highlight.
- Eliminate all 1,104 CanvasGradient creations in 48 full-rack moving frames. No gameplay physics, controls, sound or match rules changed.

Candidate push workflow #219 (`40275117286`) **SUCCESS**, 32/32 new checks, **5,249/5,249 total** across 38 suites, all four approved v3.9 audio URI hashes byte-identical. Exact candidate blob promoted to development `index.html` commit `ed1d23260fc1ea83c9a4fc390678cabfe4757c59`; independent promotion workflow #220 (`40275410786`) **SUCCESS**, 5,249/5,249 across 38 suites and all four audio hashes PASS. Jobs and decoded logs inspected. Production `main/index.html` unchanged at blob `011657038a72ff255297ca78f595eef0e67df1e3`.

**Interpretation:** The reduction in gradient allocations is deterministic, but render CPU timings are noisy and **do not show consistent improvement across viewports**. Do not claim this fixes visible jerkiness or guarantees 60fps on a physical Samsung. Render p50/p95/p99 are recorded in `POOL_WORLD_6.0_ACTIVE_RENDER_RESULTS.json` GitHub Actions artifacts.

## Visual fidelity cross-check
Compared PNG screenshots from baseline #218 and candidate #219 artifacts (same 390×844, 844×390 and 1280×800 viewport captures). Mean absolute RGB channel differences were approximately **0.0039**, **0.0068** and **0.0142** respectively (0–255 scale); pixels with any channel difference >8 were **0.020%**, **0.027%** and **0.055%** respectively. This supports close static visual fidelity, not subjective acceptance.

## Remaining blockers and next engineering tasks
- Profile total **physics + rendering + browser frame scheduling** during a real break and sustained ball motion; measure dropped frames and frame-time variance, not only render-call cost.
- Examine physics-step allocations (`balls.map`, temporary contact arrays, quaternion arrays) and GC spikes, with reproducing regression tests before changing.
- Quantify touch-to-visible-response latency using real mobile pointer events. Preserve the existing fixed 120Hz physics and calibrated power controls.
- Independent **physical Samsung Galaxy A37 and human gameplay acceptance remains absent**. No production release until independently accepted and explicitly approved.
