# Pool World v7.9 — undistorted portrait-phone pool table

Date: 25 October 2026 (UTC)
Scope: core game presentation and touch geometry only. No monetisation, multiplayer, expansion or audio changes.

## Reproduced problem
The mobile portrait media rule forced `.board{aspect-ratio:1.8}` while the actual canvas is 1100×570 (native ratio 1.92982456). This stretched all rendered pool balls vertically by about 7.2% and distorted the visible cue/shot geometry on portrait phones. The touch-to-table coordinate transformation itself was accurate, but the visual table scale was anisotropic.

A new mandatory Playwright regression tests canvas scale isotropy, touch aim, pointer coordinates, nearby-cue finger guard and JS errors at 360×800, 390×844, 844×390, 768×1024 and 1366×768.

Baseline before gameplay correction: workflow run #182 (ID 40240882025), commit 5e17aa6a61e9108f58bdeef12448c434f2914a23, **FAIL 33/35**. Both portrait-phone isotropy checks failed:
- 360×800: CSS scale anisotropy 0.06718854.
- 390×844: CSS scale anisotropy 0.06722525.
All other 33 checks passed.

## Corrective change
Candidate `POOL_WORLD_6.0_STAGING_MATCH.html` commit baa9b784d33ae6584b3a53babc9779e6cf78e129 changes only the portrait-phone board aspect rule to `aspect-ratio:1100 / 570`, matching the actual canvas. Candidate Git blob: 8afce3b3389311c8f87f9ef62f22e84ac30c65a8.

Mandatory new test: `tests/test_pool60_canvas_aspect.py`, commit 5b6abc734f0e404c51866545536f0dbe1dd18fdf.
Workflow integration: `.github/workflows/poolworld-staging-tests.yml`, commit 5e17aa6a61e9108f58bdeef12448c434f2914a23.
