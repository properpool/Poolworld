# Pool World v9.3 — Swept-contact allocation rescue
Date: 26 October 2026 (UTC)
Branch: `development/poolworld-match-engine`
Preview: https://raw.githack.com/properpool/Poolworld/development/poolworld-match-engine/index.html

## Reproduced defect

During each 120Hz physics tick, `physics()` allocated a fresh `contacts=[]` array, sorted it, and for simultaneous impact groups copied a subarray with `contacts.slice(ci,end)`. The new mandatory browser regression `tests/test_pool60_contact_reuse.py` recorded actual contact-sort array identities and grouped collision slice calls across four viewports.

The pre-fix workflow #253 (run 40323884847) failed eight of 28 new checks. For a 72-frame full-rack break at synthetic 60Hz, **142 contact sorts created 142 distinct arrays** and four temporary batch slices on every viewport. A controlled three-ball simultaneous collision created another temporary batch slice. These were observed allocations, not inferred performance gains.

## Correction

Gameplay candidate commit `e885375c86330b5090533d3657384429d4f24c15` (blob `eced31d95bd6b45b44d68cf73255840ee59c1a0e`) introduces one reusable swept-contact list, clears its length each physics tick, and passes the existing list plus `start,end` bounds to the simultaneous-contact solver. The solver retains its original default array API, pair order, 32 Jacobi iterations, double-precision coupling, collision energy limits, and match logic. No audio data, visual textures, or production files were changed.

The candidate workflow #254 (run 40323935905) **passed**. All 28 new checks passed: the same 142 contact sorts now use **one array**, with **zero** temporary contact-batch slices across all four viewports. The three-ball contact retained object momentum transfer, finite positions/velocities and energy bound (36 before, approximately 33.816 after). All existing suites passed; total **5,537/5,537 checks across 44 suites**. All four approved v3.9 ball, cue, rail and pocket audio data remained byte-identical.

Promoted the exact passing candidate blob to development `index.html` in commit `4003810d8e2ae2bb7e04bd3eaf9851ac281bfe8f`. Independent promotion workflow #255 (run 40324365599) was still in progress when this log was written; verify completion, jobs and decoded logs before claiming it passed. The test-file-only workflow #252 (run 40323860815) passed the earlier 43 suites; baseline workflow #253 failed by design. Documentation push also triggers a new workflow requiring independent verification.

Production `main/index.html` was checked and remains blob `011657038a72ff255297ca78f595eef0e67df1e3`.

## Limits and next work

The improvement is a **verified reduction in per-tick JavaScript allocations**, not a proven reduction in phone frame times, stutter, GPU latency or power-control complaints. Browser CPU timing was not a controlled same-run before/after comparison. No physical Samsung Galaxy A37 testing or independent human acceptance has occurred; the user's reported weak/jerky gameplay remains a release blocker. Next, profile real requestAnimationFrame p95/p99 under full-rack collisions, GC pauses and touch-to-visible responsiveness, reproduce a measured defect, add a mandatory regression and fix only demonstrated causes. Do not touch production without independent physical-device/human acceptance and explicit user approval. No monetisation, multiplayer, marketing or expansion.
