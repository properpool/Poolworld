# Pool World v9.0 — visible ball-rotation interpolation rescue
Date: 2026-10-26 UTC
Branch: `development/poolworld-match-engine`
Production: `main/index.html` unchanged (blob `011657038a72ff255297ca78f595eef0e67df1e3`).

## Reproduced defect
v8.9 interpolated drawn ball x/y between fixed 120 Hz physics ticks but rendered cue-ball measle dots and object-ball stripes using the *current* `rollQ` only. This produced discontinuous visible orientation even with smooth ball centers.

Mandatory new browser test `tests/test_pool60_rotation_interpolation.py` (`ef443cbdc045741f39a2b7a92eb89dec4748fe1c`) measures actual quaternions passed into `rollMarker` by canvas rendering across 390x844, 844x390, 768x1024 and 1366x768 at synthetic 60/90/144 Hz. Workflow registration: `ec9fae81438018e91c9a738160cd114f7f879f79`.

**Unfixed baseline:** workflow #238, ID `40300551419`, FAILED: **40/56** new checks, 16 genuine failures. The cue's angular step jitter (max relative to mean) was **0.6721 at 60Hz, 0.6222 at 90Hz and 1.0 at 144Hz** in each viewport. Drawing the same physical state at 25% versus 75% of a physics tick produced **zero visible orientation change**. Existing 40 suites remained green.

## Correction
Gameplay commit `fabcc5053c9117028d327b8bf3d46679fd97fe49`; candidate blob `1be25dac11e1d986ba8ee6ccfffa027526e040f4`.

- Reuse per-ball previous-orientation and visual-orientation buffers.
- Capture `rollQ` at the start of every 120Hz physics step and seed buffers at shot start.
- Apply shortest-arc normalized quaternion interpolation to *rendered* orientation using the same accumulator alpha as drawn x/y.
- Pass visual orientation to both the cue-ball measle-dot renderer and striped-ball projection.
- Preserve authoritative `rollQ`, collision physics, match rules, shot power, and undo snapshots; no per-frame quaternion array allocations.
