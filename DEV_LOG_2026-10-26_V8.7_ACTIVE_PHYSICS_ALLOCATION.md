# Pool World v8.7 — active 120 Hz physics allocation reduction
Date: 2026-10-26 (UTC). Branch: `development/poolworld-match-engine`.

## Defect reproduced
The v8.6 engine created a fresh `balls.map(b=>[b.x,b.y])` snapshot every 120 Hz physics tick and created two new four-element arrays on every moving ball's `rotateRoll` call (`next` and `next.map`). This generated unnecessary short-lived objects during active full-rack play and could contribute to garbage collection pressure. This is a deterministic allocation issue, NOT proof of visible Samsung stutter.

Mandatory regression added to existing `tests/test_pool60_active_render.py` (commit `55681b8ef60b9d47abf9a2c33529ae1f1af24e7d`). It checks active shots on 390x844, 844x390, 768x1024 and 1366x768, zero per-tick rack/rotation map allocations, stable normalized rolling quaternion identity, and independently preserved shot snapshot orientation. Baseline workflow #222 (ID 40279971652) FAILED 36/48 new suite checks (12 genuine new failures). Across 48 active frames on each viewport it measured 95 physics rack snapshot maps and 112 quaternion maps; the quaternion object identity changed. Baseline logs and job status inspected.
