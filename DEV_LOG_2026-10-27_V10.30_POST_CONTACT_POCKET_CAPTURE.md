# Pool World v10.30 — post-contact pocket capture before settlement
Date: 27 October 2026 UTC. Development-only; production is release-blocked.

## Reproducible gameplay defect
The 120Hz physics tick checked swept pocket capture before ball-ball contact resolution and rail/jaw-aware overlap projection. A late collision could then move a resting object ball into the actual circular pocket well **after** the only capture check. When all balls were already below the settle threshold, the shot resolved immediately; no next tick captured that ball. The ball could remain visibly in a pocket well and fail to score.

Deterministic fixture: top side pocket centre (550,70), object ball 1 initially (550,90.5), object ball 9 (550,113.2), both stationary. Contact correction moves ball 1 to y=89.633, inside the existing 19.98-unit capture radius. Original code settled the shot without pocketing it. Mirrored bottom pocket at y=500 reproduces the same fault. A 1.6-unit further-away near miss must remain unpotted.

## Correction
After the existing contact, jaw, rail and overlap projection, run one final **endpoint-only** pocket-well check using the exact existing squared capture radius. Capture via the original pocketBall() path, preserving scoring, sink visuals and recorded sound. This does not alter 120Hz physics timing, calibrated shotSpeed, collision impulses, rail geometry, swept-pocket checks, the six-pocket layout, match rules or the four approved audio URI bytes.
