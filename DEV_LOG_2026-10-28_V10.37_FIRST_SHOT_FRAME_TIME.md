# Pool World v10.37 — first-shot frame-time ownership (28 October 2026)

## User-visible defect reproduced
If SHOOT is pressed late within a throttled 120–320ms browser animation-frame interval, the existing frame loop charged the entire previous frame gap to a shot that had existed for only 28ms. The first visible frame could therefore advance eight 120Hz physics ticks instead of the three ticks warranted by post-input time. A 75% shot advanced about 25.89 table pixels rather than 9.74 pixels in the 120ms baseline case, creating a large first-frame jump; unused pre-shot debt also accelerated the following frame.

## Gameplay correction
`shoot()` records `performance.now()` and marks the first shot frame pending. On the first `requestAnimationFrame` callback, the loop only advances the simulation for elapsed time after the SHOOT input, if the input timestamp falls within the previous frame interval. Existing 120Hz fixed-step physics, shot-speed calibration, collision rules, pocket capture, full-match rules, visual sprites and four approved audio data URIs remain unchanged. The pending flag is retired at shot completion or rack reset.
