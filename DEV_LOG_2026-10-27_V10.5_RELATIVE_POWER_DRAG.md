# Pool World v10.5 — relative touchscreen power drag (27 October 2026)

## User-visible defect
The power handle previously discarded the strength already selected whenever the player moved a finger more than five CSS pixels. A downward 12px pull from an existing 45% strength dropped the displayed strength to roughly 10% on a 320px-high track, rather than increasing it. The same gesture from a 75% selection also dropped to ~10%. An upward movement used an unrelated absolute track position, so it could also jump the strength unpredictably. These are reproducible weak-shot control defects, not speculative CPU optimisations.

## Reproducing mandatory regression
- New `tests/test_pool60_relative_power_drag.py` commit `572bd07fa059c41c98c886a4b8ee5dfadbb61bb8`, registered in `.github/workflows/poolworld-staging-tests.yml` commit `b354ebaf30468dbd64f49acb0925a26bba77e730`.
- 204 checks across 390x844, 844x390, 768x1024, and 1366x768. Real Chromium pointer drags from 25%, 45%, 75%, with signed 12px and 24px movements, verify expected relative power, direction, absence of premature shots, release retention and actual cue impulse after pressing SHOOT.
- Original baseline workflow #324 (40426978544) FAILED **73/204**, demonstrating 131 failed checks, while previous suites and audio integrity passed. Test-only workflow #323 (40426967441) SUCCESS on all previous suites.
- First candidate workflow #325 (40427027473) FAILED 8 legacy quick-release assertions, because those tests encoded the now-invalid absolute-to-minimum power mapping. They observed the correct new stronger physical impulse; the old expected value was lower.
- Corrected existing quick-release regression in commit `b19583bfafb0ffa3bbf6da8f121382cb85e2699a` to require the retained 45% starting selection, without relaxing its actual cue-speed tolerance.

## Fix
- Staging gameplay commit `79f08036286071ca42e6edc33d8565d312bee6b1`, blob `21deeb4c65bcc3a939e727fe9a163d0babe1f86a`.
- Added `powerFromDrag(dy, initial, height)` to interpolate **from the existing selected strength** to 100% on downward pulls or to 5% on upward pulls, with the original 65px / 65%-track distance scaling.
- Both pointermove and pointerup now use the same signed relative mapping, including coalesced fast-release events.
- Preserved the 5px wobble dead zone, pull-to-fire threshold, cancel restoration, tap-to-select, existing calibrated shotSpeed curve, all six pockets, rules, visuals and approved audio URIs.

## Limits and release gate
The tests are automated Chromium pointer tests, not physical Samsung Galaxy A37 touch input, measured on-device shot strength, frame rate, display latency or human acceptance. No physical-device acceptance was performed. Production must remain untouched until independent Samsung/human acceptance and explicit user approval. Do not request user testing of unfinished builds.
