# Pool World v9.5 — Active drawing and rail-loop allocation rescue
**Date:** 26 October 2026 (UTC)  
**Branch:** `development/poolworld-match-engine`  
**Status:** Candidate and independently promoted development preview passed browser CI. **Physical Samsung Galaxy A37 acceptance remains outstanding and release-blocking.**

## Reproduced defect
The previous active gameplay path allocated temporary arrays even when ball geometry was unchanged:
- `constrainRail` constructed a fresh `['x','y']` iterable for each per-ball rail constraint invocation at 120Hz.
- `rollMarker` returned a new three-element array for each rotating object-ball stripe and cue-ball measle dot, while the cue marker directions were rebuilt each draw.

New mandatory `tests/test_pool60_active_draw_allocations.py` exercises four viewport sizes (390×844, 844×390, 768×1024, 1366×768), 72 moving full-rack frames per viewport, quaternion output identity and mathematical equivalence, legacy marker API, RETRY SHOT restoration, and actual browser-scheduled requestAnimationFrame diagnostics. Test commit `25a573257f35eeeb18336a035566fcb3cdd80ba4`; CI workflow registration commit `50e6cf87154a2f5032104a75024d78302a17345a`.

**Before the fix:** Baseline workflow **#263** (`40340903812`) failed 20 of 52 new checks (32/52 passed), consistently measuring **4,544** short-lived rail-axis iterable instances and **936** marker output arrays in each 72-frame full-rack simulation. It also demonstrated no reusable marker output. Test-file-only workflow **#262** (`40340880423`) passed the prior 45 suites.

## Corrective implementation
Candidate commit `722ce19fe240c31a7d53084171ff2358830bad18`, staging HTML blob `c2ea02f7066dd6289db94af6f844441128099182`:
1. Iterate the two rail axes by numeric index instead of creating a two-element array for each ball.
2. Keep six cue-ball marker directions and the stripe axis in static arrays.
3. Add an optional caller-supplied output vector to `rollMarker`, reusing a single scratch vector for all active drawing. Calls without that vector continue returning an independent array, preserving the original API and quaternion rotation math.

**After the fix:** All four viewports measured **0** rail-axis iterable allocations and **0** marker output allocations across 72 frames, with **936** marker scratch-vector uses. Ball state remained finite; the original vector-return API and RETRY SHOT snapshot restoration passed. These are directly measured allocation-count improvements, **not** a measured physical-phone speedup.
