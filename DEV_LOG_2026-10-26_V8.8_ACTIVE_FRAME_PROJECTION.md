# Pool World v8.8 — active-frame contact-projection profiling and rescue

Date: 26 October 2026 (Europe/London). Development branch: `development/poolworld-match-engine`.

## Defect and reproduction

The physics loop invoked the expensive rail/jaw overlap projector after **every** physics tick containing a detected object-ball contact, even when the ordinary equal-mass collision solver had already separated all balls beyond the projector's own 0.002-table-unit tolerance. The projector allocates a filtered/sorted active-ball array and may perform up to 64 jaw-aware sweeps, so invoking it for a no-op contact wastes work on the active gameplay path.

Added `tests/test_pool60_active_frame_latency.py` (commit `7f956385b702b7f01c4f5b5d662caa1ad0604f6d`) and wired it into `.github/workflows/poolworld-staging-tests.yml` (commit `d56ed6cd78d9f6523fbedb29f1f97ac4a9301bf2`). This new suite profiles 72 actual rendered full-rack frames per viewport, records frame/physics/render CPU p50/p95/p99, exercises a real Playwright pointer event followed by a render, and verifies the rail-side solver remains active for a dense three-ball chain. Tested 390x844, 844x390, 768x1024 and 1366x768.

**Red baseline:** GitHub Actions #228 (`40286983108`) FAILED the new suite **32/36**, with four genuine central-contact failures. Every viewport performed one redundant projector call for a shallow two-ball central collision that had already been fully separated; final penetration was -0.002 units. Rail-side chains correctly invoked projection and stayed on the cloth. The prior workflow #227 (`40286965588`) passed the original 5,265 checks, before the new suite was mandatory.

## Fix and proof

Candidate commit `b7de71e6fd1d6a3cc12cdf9ab0a6fe4b03a6c82b`, blob `4c0a610b5a0efd497c7d8fb1b1bf83025ce74aa6`, adds a squared-distance residual-overlap precheck after collision impulses. The projector is invoked **only** if an unpotted ball pair still overlaps by more than its existing 0.002-unit correction threshold. If no such pair exists, the original projector would make zero corrections, so skipping it does not alter the resulting physics state. Deep rail-side and jaw chains continue through the original full solver.

**Green candidate:** GitHub Actions #229 (`40287060219`) SUCCESS **5,301/5,301 checks across 39 suites**, including new **36/36**. Center projector calls decreased 1→0 on all four viewports, while dense rail chains retained 1 call and legal separation. During 72 synthetic full-rack frames, the projector call count was 9 in baseline versus 7 in candidate, with object-ball momentum transfer preserved.

**Independent development preview promotion:** Exact candidate blob copied to development `index.html` at commit `aa475d81a28504145b2155e577772a25e903779c`. GitHub Actions #230 (`40287627822`) SUCCESS **5,301/5,301 across 39 suites**, new **36/36**, all four approved v3.9 audio data URI integrity checks PASS. Jobs and decoded logs were inspected for #227–230.

## Performance measurements and limits

Baseline headless Chromium active-frame p95 CPU across the four viewports: **2.6, 2.7, 2.3, 1.3 ms**. Candidate: **1.1, 1.7, 0.9, 0.9 ms**. These measurements come from **different CI runners** and are not controlled paired hardware benchmarks; do not present them as a proven FPS improvement or a causal speedup. The synthetic pointer-to-next-render elapsed values in the candidate were approximately **1.8–2.5 ms**, but this is a manually advanced headless-browser test, **not** end-to-end touchscreen latency or physical display response.

No physical Samsung Galaxy A37 or human gameplay acceptance has occurred. The user still reports weak shots and jerky motion; release remains blocked until independently tested on the actual device and explicitly approved. Production `main/index.html` was not modified; its blob SHA remained `011657038a72ff255297ca78f595eef0e67df1e3`.
