# Pool World — v6.3 touch-aim safety and scattered-pot acceptance

Date: 25 October 2026. Repo: `properpool/Poolworld`. Development branch: `development/poolworld-match-engine`.

## Actual gameplay code change
- A finger landing within **20 CSS pixels** of the cue ball on a touchscreen no longer snaps the aim angle. The guard scales with the canvas width, so portrait and landscape touch targets behave consistently. Dragging away from the ball or tapping further away still aims normally; precision mode remains available.
- If a mobile or pointer aiming gesture is cancelled by the browser/OS, the angle is restored to its value at the beginning of that gesture instead of silently retaining a partial adjustment.
- This does **not** change shot power, collision impulses, cushion/jaw geometry, match rules, ball rolling or approved v3.9 sound payloads.

## New required browser acceptance
Added `tests/test_pool60_scattered_touch_pots.py` and required it in `.github/workflows/poolworld-staging-tests.yml`. The suite covers portrait (390x844) and landscape (844x390), finger landing near the cue, deliberate tap aiming, cancelled precision drag, and **24 cut-shot pots** (all six pockets, ±12-degree cuts, both viewports) with 14 other live balls scattered around each controlled layout. Shots use Chromium touchscreen taps to aim and fire, with actual physics, first-ball contact, settled state and turn/group rule checks. 82/82 checks passed on GitHub Actions run #89.

## Remaining limitations
These are controlled layouts and automated Chromium touch emulation, **not** human gameplay or a physical Samsung test. The 24 cut shots used clear corridors and precise calculated ghost-ball aim points; they do not prove that an unassisted player can reliably pot in arbitrary congested matches. Next investigate actual finger-aim tolerance under imprecise touches, more natural clustered ball layouts, and long-match stress. Preserve approved sound payloads and the production release gate.
